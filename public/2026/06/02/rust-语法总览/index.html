所有权 , 引用与借用 , slice

Rust 的核心内存安全机制建立在所有权（Ownership）、**借用（Borrowing）**与 切片（Slice） 之上。以下是现代 Rust 中最常用且标准的语法规范。

所有权（Ownership）核心规则

Rust 中每个值都有一个所有者（变量），同一时间只能有一个所有者。当所有者离开作用域时，值会被自动释放（Drop）。

语义分化：Move 与 Copy

  • Move 语义（堆内存/复杂类型）：赋值或传参时转移所有权，原变量失效。
  • Copy 语义（栈内存/基础类型）：实现了 Copy Trait 的类型（如 i32, bool, char 等），赋值时自动深拷贝，原变量依然有效。

引用与借用（References & Borrowing）

引用与借用的关系

通过“借用”（创建指针），可以在不获取所有权的情况下使用数据。

引用（Reference）：是一种数据类型或语言机制。它是指向某块内存地址的指针，并携带着编译器施加的类型安全与生命周期信息（如 &T 和 &mut T）。

借用（Borrowing）：是一种行为或语义过程。指在不获取数据所有权（Ownership）的前提下，临时使用该数据。创建引用的这个“动作”本身，在语义上就叫做“借用”。

比喻：

你有一本书（所有权）。

你的朋友想看，你把书借给他（借用的行为）。

朋友手里拿到的那张“借书凭证”或访问权（引用的实体）。

即: 借用是逻辑概念,引用是实现方式

借用规则（二选一原则）

在任意给定作用域内，只允许满足以下两个条件之一：

  1. 任意多个不可变引用 (&T)
  2. 有且仅有一个可变引用 (&mut T)

推荐模式：形参写 &str 或 &[T]，可同时兼容字面量、堆分配对象以及切片自身。

使用 .clone() / .to_owned() 显式避开生命周期复杂性

当需要独立所有权时，显式深拷贝：

  • &str $\rightarrow$ String：使用 s.to_string() 或 s.to_owned()
  • 实现了 Clone 的结构体/集合：使用 obj.clone()

编码避坑指南

  1. 悬垂引用（Dangling Reference）：Rust 编译器在编译期就会杜绝“返回函数内部局部变量引用”的操作。
  2. 迭代器失效防护：在遍历容器时修改容器会导致编译报错。

package , crate 和 module

在现代 Rust（Rust 2018 / 2021 / 2024 Edition）中，代码组织遵循“约定优于配置”原则。以下是标准且通用的 Package、Crate 与 Module 语法规范。

Package（包）与依赖管理

Package 是由 Cargo.toml 管理的项目文件集合。

依赖引入 (Cargo.toml)

Crate（单元包）入口约定

Rust 依靠默认文件系统路径自动识别 Crate 树的根节点，无需手动配置：

  • Library Crate（库）：src/lib.rs
  • Binary Crate（可执行程序）：src/main.rs
  • Integration Tests（集成测试）：tests/xxx.rs（tests/ 下的每一个 .rs 文件都会被独立编译为一个测试 Crate）

Module（模块）声明与组织

在父文件（如 lib.rs 或 main.rs）中使用 mod 关键字声明并挂载子模块。

基础声明语法

  • mod foo;：声明私有模块（仅限当前 Crate 内部访问）。
  • pub mod foo;：声明公有模块（可被外部 Crate 或上层导入访问）。
  • pub(crate) mod foo;：限制可见性（仅在当前 Crate 内部任意位置可见，对外隐藏）。

结构模式 A：单文件模式 (Single File)

适用于功能较简单、无需再往下拆分的文件。

结构模式 B：同名文件 + 同名目录模式 (Modern Submodule)

适用于模块变得复杂、需要继续拆分出子模块的场景（官方推荐标准）。

路径导入

模块重导出 (pub use)

用在模块入口文件中，用于屏蔽内部复杂拆分，向外部暴露干净统一的接口。

编码禁忌（旧语法黑名单）

  1. 不要写 extern crate xxx;：直接在 Cargo.toml 中声明依赖即可，Rust 编译器会自动处理引入。
  2. 尽量避免使用 mod.rs：除非是在维护古老的 Rust 代码库，新项目优先使用“同名 .rs 文件”作为文件夹入口，避免 IDE 中打开一堆同名标签页。
  3. 不要使用 #[path = "..."] 属性：让 Rust 依据标准目录路径自动匹配，避免破坏团队统一的文件查找逻辑。

泛型、Trait 与生命周期语法总结

Rust 的类型系统依赖 泛型（Generics） 实现抽象，Trait（特质） 定义行为约束，以及 生命周期（Lifetimes） 保证引用引用的有效性。以下是现代 Rust 中最常用且标准的语法与惯用法总结。

生命周期省略规则（Elision Rules）

无需在任何地方都手动写 'a。编译器会在以下模式下自动推导：

  1. 每一个引用参数都会获得独立的生命周期参数。
  2. 如果只有一个输入引用参数，该生命周期会被赋给所有的输出引用。
  3. 如果输入参数包含 &self 或 &mut self，self 的生命周期会被赋给所有的输出引用。

Trait 约束的合理选择

  • 参数传递轻量对象或视图时，优先使用 &str / &[T] 而非具体的 &String / &Vec<T>。
  • 需要类型支持基本比较时，使用 PartialOrd / Ord；需要格式化打印时，使用 Debug / Display。
