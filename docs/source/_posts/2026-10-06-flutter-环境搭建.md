# dart 项目

**傻逼 `dart` 官方并不支持设置缩进宽度. 这实质上是因为 `flutter` 的声明式 UI 需要很深的缩进深度, 但是官方既没有勇气在遇到不符合他们尿性的格式时直接报错, 又没有能力修正这一设计错误, 于是出现了这种想要模仿 go 语言结果模仿的结果就成了东施效颦的效果**

## 新建

```bash
dart create dart-hello
```

这会生成如下结构

```bash
E:.
│  .gitignore                # Git 忽略配置：排除 .dart_tool、build/ 等不需要提交的文件
│  analysis_options.yaml     # 傻逼 Dart 静态分析规则：控制 lint、代码风格、警告级别
│  CHANGELOG.md              # 版本更新日志：记录每个版本的改动
│  pubspec.lock              # 依赖锁定文件：锁定所有包的具体版本，保证多人协作一致
│  pubspec.yaml              # 项目核心配置：项目名、版本、SDK 约束、依赖声明
│  README.md                 # 项目说明文档
│
├─.dart_tool                 # Dart 自动生成的缓存目录，不要手动修改
│  │  package_config.json    # 记录每个依赖包在本地的实际路径
│  │  package_graph.json     # 依赖关系图，用于分析包之间的依赖
│  │
│  └─pub
│      └─bin
│          └─dart_hello
│                  dart_hello.dart-3.13.5.snapshot  # 编译缓存快照，加速再次运行
│
├─.vscode                    # VSCode 编辑器配置目录
│      launch.json           # 调试配置：定义 F5 启动哪个文件、用什么配置运行
│
├─bin                        # 可执行脚本入口目录（类似 main 函数所在目录）
│      dart_hello.dart       # 程序入口文件：包含 main() 函数，dart run 默认执行这里
│
├─lib                        # 库代码目录：存放可被外部 import 的公共代码
│      dart_hello.dart       # 库文件：定义项目对外暴露的类、函数、常量
│
└─test                       # 单元测试目录
        dart_hello_test.dart # 测试文件：对 lib/ 中的代码编写单元测试
```

## launch.json

```json
{
    "configurations": [
        {
            "name": "Dart",
            "type": "dart",
            "request": "launch",
            "program": "bin/dart_hello.dart"
        }
    ]
}
```
