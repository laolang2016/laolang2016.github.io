### 文件内容

#### Dockerfile

```yaml
FROM alpine:3.24

# 镜像元数据
LABEL org.opencontainers.image.authors="laolang <xiaodaima2016@163.com>" \
      org.opencontainers.image.title="devstudio-go-server" \
      org.opencontainers.image.description="DevStudio Go 后端服务" \
      org.opencontainers.image.version="0.0.1" \
      org.opencontainers.image.source="https://gitee.com/ghost-devstudio/devstudio" \
      org.opencontainers.image.licenses="MIT"

# 运行必需的包：CA 证书（HTTPS 调用）和时区数据
RUN apk add --no-cache ca-certificates tzdata

# 创建非 root 用户
RUN addgroup -g 1000 -S appgroup && adduser -u 1000 -S -G appgroup appuser

WORKDIR /app

# 复制整个 dist 目录（含 server、version.txt、.env）
COPY --chown=appuser:appgroup dist/ ./

# 如果可执行文件没有执行权限，这里补一下
RUN chmod +x ./server

# 预先创建 logs 目录并授权
RUN mkdir -p /app/logs && chown -R appuser:appgroup /app

VOLUME ["/app/logs"]

USER appuser

EXPOSE 8080

ENV GIN_MODE=release

CMD ["./server"]
```

#### Taskfile.yml

> https://taskfile.dev/

```yaml
# yaml-language-server: $schema=https://taskfile.dev/schema.json

version: '3'

vars:
  GREETING: Hello, world!
  VERSION: 0.0.1

tasks:
  default:
    desc: Print a greeting message
    cmds:
      - echo "{{.GREETING}}"
    silent: true

  format:
    cmds:
      - go tool goimports -w .

  build:
    cmds:
      - CGO_ENABLED=0 go build -ldflags="-s -w -X main.Version=v{{.VERSION}} -X main.GitCommit=$(git rev-parse --short HEAD)" -o ./dist/server ./cmd/server
      - go version -m ./dist/server > ./dist/version.txt

  clean:
    cmds:
      - rm -rf dist

  docker:
    cmds:
      - docker rmi ghost/dagu-go:{{.VERSION}} 2>/dev/null || true
      - docker build -t ghost/dagu-go:{{.VERSION}} .
```

#### server.go

```go
package main

import (
        "flag"
        "fmt"
        "net/http"
        "os"

        "github.com/gin-gonic/gin"
)

var (
        Version   = "dev"
        GitCommit = "none"
)

func printVersion() {
        showVersion := flag.Bool("v", false, "显示版本信息")
        flag.BoolVar(showVersion, "version", false, "显示版本信息")
        flag.Parse()

        if *showVersion {
                fmt.Printf("Version:    %s\n", Version)
                fmt.Printf("Git Commit: %s\n", GitCommit)
                os.Exit(0)
        }
}

func main() {
        printVersion()

        r := gin.Default()

        r.GET("/check", func(c *gin.Context) {
                c.JSON(http.StatusOK, gin.H{
                        "success": true,
                        "code":    "200",
                        "msg":     "操作成功",
                        "data":    "It' ok!",
                })
        })

        r.GET("/ping", func(c *gin.Context) {
                c.JSON(http.StatusOK, gin.H{
                        "success": true,
                        "code":    "200",
                        "msg":     "操作成功",
                        "data":    "pong",
                })
        })

        r.Run()
}
```

  namespace: 'default'

  containers:

主要改动内容

根据差异文件，本次针对 `ingress-nginx` 的配置主要进行了四大类定制，主要目的是**适配国内网络环境**以及**裸金属/虚拟机节点部署**。

1. 镜像仓库替换（适配国内网络）
将官方不可达的镜像仓库替换为阿里云镜像仓库，并修改了对应的镜像名称：
*   **全局 Registry**：`registry.k8s.io` 替换为 `registry.cn-hangzhou.aliyuncs.com`
*   **Controller 镜像**：`ingress-nginx/controller` 替换为 `google_containers/nginx-ingress-controller`
*   **Webhook 镜像**：`ingress-nginx/kube-webhook-certgen` 替换为 `google_containers/kube-webhook-certgen`

2. 固定镜像版本（取消 SHA 校验）
*   注释了 `digest` 和 `digestChroot` 的 SHA256 校验值。
*   将 Webhook 镜像的 `tag` 从 `v1.6.9` 升级为 `v1.15.1`。
*   *说明*：由于镜像仓库更换，镜像的 SHA256 哈希值已发生变化，必须注释掉原校验值，否则 K8s 会因哈希不匹配导致拉取失败。

3. 网络策略与部署模式调整（适配宿主网络）
为了直接占用宿主机 80/443 端口，修改了网络及部署形态：
*   **启用宿主网络**：`hostNetwork` 设为 `true`。
*   **调整 DNS 策略**：`dnsPolicy` 设为 `ClusterFirstWithHostNet`，确保使用宿主网络时 Pod 仍能解析集群内部服务。
*   **部署类型变更**：`kind` 从 `Deployment` 改为 `DaemonSet`（确保每个符合条件的节点都运行一个实例）。
*   **新增节点选择器**：增加 `nodeSelector: ingress: "true"`，配合 DaemonSet 控制 Pod 仅调度到特定节点。
*   **Service 类型变更**：`type` 从 `LoadBalancer` 改为 `ClusterIP`（因已使用 hostNetwork，无需外部负载均衡器）。

4. 关闭准入 Webhook 功能
*   将 `admissionWebhooks.enabled` 设为 `false`。
*   *说明*：关闭了 Ingress 规则语法校验功能。通常在测试环境或为了避免 Webhook 证书过期导致集群故障时会选择关闭。

> **⚠️ 注意事项**：由于开启了 `hostNetwork: true`，Ingress Pod 将直接监听节点的 80/443 端口。若节点上已存在占用该端口的服务（如宿主机原有的 Nginx），需提前停止清理，否则会导致 Pod 启动失败。
